# ReadLab X 官网设计文档

这份文档定义 ReadLab X 官网的视觉方向、信息结构、主题系统、
国际化策略，以及实现约束。目标不是做一张“看起来高级”的静态页面，
而是建立一套能指导设计、内容、前端实现和后续迭代的统一标准。

ReadLab X 的官网承担两类任务。第一，它要作为“阅读实验室”的品牌首页，
传达产品的思考气质、研究方法和核心价值。第二，它要作为项目展示入口，
承载项目介绍、案例、实验性内容和后续扩展页面。因此，设计必须同时满足
品牌表达、长期阅读体验、内容扩展性和工程可维护性。

## 项目目标

官网设计必须围绕以下目标展开，而不是围绕视觉效果堆砌页面。

- 建立一个安静、克制、可信的品牌第一印象。
- 让用户快速理解 ReadLab X 是“阅读实验室”，而不是普通内容站。
- 支撑长时间阅读和思考，不用视觉噪音抢走注意力。
- 为首页和项目展示页建立统一的视觉与组件语言。
- 兼容国际化、三种主题模式、SEO 和响应式布局。

ReadLab X 不采用“炫技型科技官网”的视觉路线。它更像一间经过布置的阅读
画廊：内容是主角，页面只是舞台。

## 品牌与风格定位

ReadLab X 采用 Minimalism 家族中的“理性极简”分支。这里的极简不是“删除
一切”，而是对每一个视觉元素都追问一个问题：它是否帮助用户理解内容、
区分层级、建立信任，或者触发行动。如果不能，它就不该存在。

这个风格适合 ReadLab X，原因有三点。第一，产品本身属于阅读、写作、知识
组织和项目展示场景，天然需要清晰结构和长时间停留。第二，品牌气质偏理性、
研究型和高质量内容导向，不适合过度拟物、过度娱乐化或过度商业化。第三，
官网未来需要承载项目展示页、案例页和深度说明页，视觉系统必须对内容有
包容性，而不是只能服务首页首屏。

整体氛围需要呈现出以下关键词：

- 安静
- 清晰
- 稳定
- 有思考空间
- 高端但不奢靡
- 科学感与编辑感并存

## 视觉原则

视觉系统遵循“少即是多，但少必须有秩序”的原则。页面的完成度来自节奏、
栅格、留白和排版，而不是来自强装饰。

### 排版原则

排版是官网的主结构。标题、引导文、正文、辅助说明、标签和导航都必须拥有
清晰的尺寸级差和间距规则。标题承担焦点功能，正文承担理解功能，辅助信息
承担引导和上下文补充功能。任何层级都不能模糊。

推荐建立以下节奏：

- Hero 标题：强调品牌主张，视觉最强。
- 模块标题：引导阅读路径，保持一致语气。
- 正文：宽松行高，保证长段落可读。
- 辅助标签：小号大写或半大写，用于建立模块语义。

### 留白原则

留白不是“空着”，而是用来隔离信息、建立呼吸感和强化主次。大留白用于模块
与模块之间，小留白用于文本层级内部。留白必须服务阅读路径，而不是服务“看
起来高级”的主观感受。

### 装饰原则

装饰被压缩到最少。阴影仅在需要层次提示时才出现，并且必须非常轻。背景不做
复杂纹理，不做夸张渐变，不做厚重卡片堆叠。边框、分割线和图标都保持细而稳
定的线宽。页面的质感来自秩序，不来自表面华丽。

## 颜色系统

ReadLab X 的主题色固定为以下五个色值：

- `#a8eb12`
- `#00bf72`
- `#008793`
- `#004d7a`
- `#051937`

这组颜色承担品牌识别，不承担页面铺满式上色。官网依然要坚持极简原则，因此
主页面配色以中性色和大面积留白为基础，品牌色只作为焦点、强调、状态反馈和
局部图形表达使用。

### 颜色使用策略

- `#051937` 作为深色文字、深色按钮、暗色模式主背景的核心色。
- `#004d7a` 和 `#008793` 作为链接、强调模块、数据或结构性高亮色。
- `#00bf72` 和 `#a8eb12` 作为品牌生命力的高亮层，仅用于关键按钮、图形
  局部、悬停反馈和少量强调标签。

### 页面层级建议

- 大面积背景：中性白、暖灰白、极浅灰蓝。
- 正文文字：深蓝黑，而不是纯黑。
- 分割线：低对比浅灰线。
- 品牌重点：小面积使用五色渐变或五色分段渐变。

> 注意：品牌色是“焦点系统”，不是“页面底色系统”。如果把五色渐变铺满整站，
> 极简气质会立即消失。

## 页面结构

官网第一阶段至少包含两个核心页面：首页和项目展示页。它们共享同一套布局、
导航、页脚和主题体系。

## 首页设计

首页承担品牌解释和行动引导，结构建议如下：

1. 顶部导航  
   包含品牌标识、核心导航、语言切换、主题切换，以及主要 CTA。
2. Hero 区  
   用一句品牌主张解释 ReadLab X 是什么，再用一段说明解释它解决什么问题。
3. 能力说明区  
   说明阅读、整理、连接、输出这四类核心能力。
4. 价值场景区  
   面向研究者、写作者、长期学习者和项目创作者说明适用场景。
5. 项目预告区  
   作为首页到项目展示页的桥梁，展示若干精选项目卡片。
6. 底部 CTA 与页脚  
   提供进一步联系、订阅、项目浏览或产品了解入口。

首页必须避免两种误区。第一，不要把首页写成“功能清单堆叠”。第二，不要把
首页做成过分情绪化的品牌大片而缺少信息。

## 项目展示页设计

项目展示页的角色不是普通作品列表，而是“阅读实验室成果橱窗”。它要兼顾浏览
效率和内容沉浸感。

建议项目页采用以下结构：

1. 页面标题与筛选说明  
   用一句话说明这些项目是什么，以及用户能从中看到什么。
2. 项目列表区  
   支持按主题、状态、媒介或阶段进行筛选。
3. 项目卡片  
   展示标题、简述、标签、状态、年份或阶段性信息。
4. 项目详情入口  
   点击后进入项目详情页，承载更深内容。

项目卡片设计应保持克制。卡片主要依赖排版、边界和间距建立秩序，不依赖厚重
阴影和夸张交互。卡片 hover 只需轻微改变边框色、背景色或标题色即可。

## 主题系统

官网必须支持三种主题模式：

- 亮色模式
- 暗色模式
- 跟随系统

### 亮色主题

亮色主题是默认品牌展示主题。它强调干净的背景、清晰的文本层级和少量品牌色
焦点，适合首访用户和内容浏览。

### 暗色主题

暗色主题用于夜间阅读和更沉浸的展示场景。暗色不是简单反转颜色，而是重新定义
层级关系：

- 背景使用深蓝黑，而不是纯黑。
- 文本使用低眩光的浅灰白。
- 分割线和面板使用低对比度边界。
- 品牌色亮度适度提升，避免在暗背景上发灰。

### 跟随系统

跟随系统模式必须是完整的一等公民，而不是额外附加项。主题状态需要保存在本地，
并在首屏渲染前完成同步，避免闪烁。

## 国际化策略

官网必须从结构上支持 i18n，而不是等页面写完后再翻译。

第一阶段建议至少支持：

- `zh-CN`
- `en`

文案结构必须按语言资源分离，不能把文本硬编码在组件内部。URL 结构建议预留语言
前缀，例如：

- `/zh/`
- `/en/`

如果首版为了路径简洁只上线一个默认语言，也要在内容组织和 SEO 层预留多语言
扩展能力，包括：

- 文案资源文件独立存放
- 页面 meta 随语言切换
- `hreflang` 预留
- 导航、页脚、按钮和表单提示全部可翻译

## SEO 策略

ReadLab X 官网需要把 SEO 当作基础能力，而不是上线后补的工作。

### 基础 SEO

- 每个页面都有独立 `title` 和 `description`
- 每个页面设置 canonical
- 使用语义化标题结构
- 生成 sitemap 和 robots
- 配置 Open Graph 与 Twitter Card

### 多语言 SEO

如果上线多语言，必须补充：

- `hreflang`
- 不同语言页面的独立 metadata
- 不同语言的结构化数据描述

### 结构化数据

建议至少补充以下 schema：

- `Organization`
- `WebSite`
- `CollectionPage`
- `Article` 或 `CreativeWork`（用于项目详情页）

## 响应式策略

官网必须兼容桌面、平板和 H5。这里的响应式不是简单缩小元素，而是根据屏幕和
阅读方式重新安排信息密度。

### 断点建议

- 移动端：`< 768px`
- 平板端：`768px - 1199px`
- 桌面端：`>= 1200px`

### 移动端原则

- 优先保证标题、导语、主 CTA 和核心说明先可见。
- 导航收纳为轻量化菜单，但语言和主题切换仍然易于触达。
- 模块上下节奏保持充分呼吸感，不做拥挤双列。
- 项目卡片改为单列，减少横向比较负担。
- 文本宽度保持舒适，避免超长行和超小字号。

## 交互原则

交互反馈必须安静、明确、克制。

- 按钮 hover：改变边框、文字色、背景明度，避免强缩放。
- 链接 hover：下划线或颜色变化即可。
- 卡片 hover：轻微背景或边框变化即可。
- 页面动画：以淡入、轻微位移和顺滑过渡为主。

所有动画都必须为内容服务，而不是夺走内容注意力。长时间阅读不应被频繁动效
打断。

## 组件设计建议

为了让首页和项目页风格统一，建议优先建立以下基础组件：

- Header
- Footer
- ThemeToggle
- LocaleSwitcher
- Hero
- SectionHeader
- FeatureCard
- ProjectCard
- CTASection

这些组件应围绕统一的设计 token 工作，包括颜色、间距、圆角、边框、字号、
字重和动画时长。

## 设计 token 建议

建议建立以下 token 分层：

- 语义颜色：背景、文字、边界、强调、成功、警示
- 品牌颜色：五个主题色及其主题态映射
- 间距系统：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96`
- 圆角系统：`8 / 12 / 20 / 28`
- 动画时长：`120ms / 180ms / 240ms / 360ms`

主题切换时，优先切换语义颜色，不直接让组件引用硬编码色值。

## 实现建议

从技术方案看，官网推荐使用 Astro。原因如下：

- 官网以内容展示和静态输出为主，Astro 更轻。
- SEO 和静态页面生成更直接。
- 国际化和多页面组织更适合官网场景。
- 后续如果需要嵌入局部交互，也可以按岛屿方式逐步增加。

首版工程结构建议如下：

- `src/pages`：首页、项目页、项目详情页、关于页
- `src/components`：布局与展示组件
- `src/layouts`：页面骨架
- `src/styles`：全局 token 和主题样式
- `src/i18n`：语言资源与路由映射
- `public/brand`：logo 与品牌资源
- `public/icons`：favicon 与移动端图标

## 成功标准

这套官网设计在内部评审时，至少要满足以下标准：

- 首页在 5 秒内能让用户理解 ReadLab X 的定位。
- 长段阅读没有明显视觉疲劳。
- 亮色、暗色和跟随系统三种主题都保持统一气质。
- 中英文切换不破坏版式完整性。
- 项目页可自然扩展，不会因为项目数量增长而失控。
- 页面在移动端依然清晰、克制、可读。

## 下一步

这份文档完成后，下一阶段建议按以下顺序执行：

1. 基于本文档整理信息架构与页面文案。
2. 建立设计 token 与三主题变量体系。
3. 先实现首页，再实现项目展示页。
4. 接入 i18n、SEO 和响应式细节。
5. 最后补项目详情页和内容发布流程。
